# Sadhya Scanner — iPad

A native iPad build of `/staff/scan`. Same server, same endpoints, same rules —
the camera fills the screen, results take the whole display, and a scan makes a
sound.

## Getting it onto an iPad

1. `open SadhyaScanner.xcodeproj`
2. Select the **SadhyaScanner** target → **Signing & Capabilities** → pick your
   Apple ID under **Team**. The bundle id `com.scvsarigama.sadhyascanner` may
   need a suffix if it is already taken on your account.
3. Plug in the iPad (or pair it over Wi-Fi), choose it as the run destination,
   press ⌘R.
4. On the iPad: **Settings → General → VPN & Device Management** → trust the
   developer certificate. A free Apple ID signs the build for **7 days**; a paid
   developer account for a year.

On first launch it asks for the server address (e.g. `checkin.scvsarigama.org`)
and the volunteer password, then stays signed in for two weeks — the same
14-day session the browser scanner gets.

## What it does

- **Scan** — the camera reads the QR on a pass and chimes the moment it decodes,
  before the network call. Two codes in frame and it refuses to guess: both get
  a gold frame and the volunteer taps the right one.
- **Tap anywhere** on the picture to focus and expose there.
- **Count → confirm → admit**, with the under-6 rule on the confirm screen. Same
  two-step gate as the web scanner; nothing is redeemed off a single tap.
- **Give back** from the success screen (undo the scan just made) or from the
  pass panel (restore admissions counted wrong earlier).
- **Search** by name, email, or phone when a code cannot be read.

## Sounds

Synthesised at launch, no audio files: a bright bell on decode, a warmer
two-note bell on admit, a low double thud on refusal, a click on tap. Tuned in
`Core/Chime.swift` — change a frequency, not a sample.

## Server side

The app signs in through `POST /api/staff/session`, which exists only because
the web login is a server action a native client cannot post to. It calls
`signInShared` and sets the same `onam_staff` cookie. Everything after that is
the endpoints the browser scanner already uses:

| | |
|---|---|
| `GET /api/staff/session` | is this iPad still signed in |
| `GET /api/staff/lookup?token=` | resolve a scanned pass |
| `GET /api/staff/lookup?q=` | search |
| `POST /api/staff/redeem` | release admissions |
| `POST /api/staff/reverse` | give admissions back |

Cleartext HTTP is permitted to local hostnames only, so the app can be pointed
at `http://localhost:3000` during development. The real server must be HTTPS.
